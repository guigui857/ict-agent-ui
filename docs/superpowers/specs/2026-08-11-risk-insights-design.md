# 风控洞察（Risk Insights）设计

> 日期：2026-08-11 · 分支：`feature/tailadmin-ui` · 状态：已获用户确认（两节设计均通过）

## 背景与目标

在已迁移到 Tailwind UI 的 `ict-agent-fresh` 基础上，按 `docs/deep-research-report.md` 的候选能力，
实现研究报告建议但页面尚未提供的 7 项风控洞察能力。全部为**确定性计算**（复用现有七表 DuckDB 查询），
不引入模型调用。用户已确认「分阶段全做」。

## 范围

### 实现的 7 项能力
1. 客户价值—风险评分与九宫格
2. 逾期预警状态机
3. 展期识别（4 类）
4. 授信调整触发
5. 更丰富的可视化（可计算的子集）
6. 四级动作体系
7. 人工 override 审计

### 可视化边界（诚实标注）
- **可计算**：九宫格热力图、账龄结构堆叠条（月×DPD档）、客户×月份展期热力图、预警状态机列表、
  库龄堆叠条（季×库龄层）、库龄×预计毛利热力图、销售额/毛利/CM2 时序、Vintage 迁徙热力图、
  四级动作队列、override 审计记录。
- **不可计算**（七表无数据，页面标注「数据不支持」，不硬造）：项目履约 Gantt（无验收进度）、
  ROC/PR 校准图（无真实违约/坏账结果标签）、完整项目现金暴露时序（部分可近似）。

## 架构

### 后端
- 新增模块 `backend/src/ict_agent/insights.py`：确定性洞察计算，复用 `data.py`（DuckDB 访问）与
  `tools.py` 已有函数；新增参数化 SQL 放在本模块或 `data.py`。
- 新增端点（`api.py` + `service.py` 加路由/服务函数），全部 `GET /api/v1/insights/*`：
  - `customers`：客户列表（V 分 / R 分 / 九宫格档位 / 四级动作 / 预警状态）
  - `customers/{customer_id}`：单客户详情（状态机、展期识别、授信触发、四级动作、评分分解）
  - `ar-aging`：账龄结构（月 × DPD 档）
  - `inventory-aging`：库龄结构（季 × 库龄层）
  - `extension-heatmap`：客户 × 月份展期热力图数据
  - `inventory-economic`：库龄 × 预计毛利
  - `revenue-trend`：销售额 / 含税粗算毛利 / CM2 月度时序
  - `vintage`：应收风险迁徙（起始月 × 经过月）
  - `actions`：四级动作队列
  - `overrides`：override 审计记录
- 复用 `rule-runs` / `cases` 已有案件与规则信号作为四级动作的输入之一。

### 前端
- 新增导航项「**风控洞察**」（lucide 图标，App 壳侧栏加入），下分 4 个导航视图（客户洞察含列表与详情两个路由）：
  - `/insights/customers` 客户洞察：九宫格热力图 + 客户列表
  - `/insights/customers/:customerId` 客户详情：预警状态机、展期识别、授信触发、四级动作、评分分解
  - `/insights/ar` 应收预警：账龄堆叠条、展期热力图、预警状态机列表、Vintage 迁徙
  - `/insights/inventory` 库存健康：库龄堆叠条、库龄×毛利热力图
  - `/insights/governance` 治理中心：四级动作队列、override 审计记录
  - `/business` 经营分析增强：销售额/毛利/CM2 时序图
- 全部用 Tailwind + ApexCharts（沿用已迁移 UI 体系与 `ui/` 组件）。

## 口径设计（将写入 `docs/metric-contract.md` 新增小节）

### A. 客户价值—风险评分与九宫格
- **V 价值分**（越大越好，0–100）：特征 = `累计销售额`、`含税粗算毛利`（已冻结口径）、`活跃月数`
  （有销售或回款的月数）、`品类宽度`（去重品类数）、`回款稳定性`（近 6 月回款变异系数的反向）。
  每特征按全体客户经验分布 `score_i = 100 × ECDF(x_i)`（越小越好则反向）。
  默认权重：毛利 0.35 / 销售额 0.20 / 活跃月 0.15 / 品类 0.15 / 回款稳定 0.15（写入口径，注明可校准）。
- **R 风险分**（越大越差，0–100）：特征 = `最大DPD`、`超期余额占比`、`DPD90+占比`、`展期次数`、
  `展期失败率`、`授信使用率`、`30/60/90+超期率`；ECDF 反向。默认均权，注明可校准。
  **硬覆盖**：信用减值证据 / 未解决额度突破 / 高严重度失败展期 → 直接 `HIGH`，不依赖分数。
- **九宫格切档**：V、R 各自按全体客户**三分位**切 高/中/低；硬覆盖直接进高风险格。
  格子含义（照研究报告）：高价值×低风险=战略维护；高×中=控制扩张；高×高=收款/增信优先（不豁免）；
  中×低=标准额度账期；中×中=严控新增暴露；中×高=收款优先降额现金；低×低=自动化低成本服务；
  低×中=收缩信用资源；低×高=退出信用销售。

### B. 逾期预警状态机（每客户，确定性）
取最新月末应收截面：
- `NOT_DUE`：无超期。
- `PRE_DUE`：无超期但存在 `最终承诺还款日期 - 快照日期 <= pre_due_alert_days`（默认 15，可校准）。
- `DPD_1_PLUS` / `DPD_30_PLUS` / `DPD_60_PLUS`：按最大超期天数分档。
- `DPD_90_REVIEW`：最大超期 ≥ 90 天。
  - 有反证（近 3 月回款 > 0 且非黑名单且无失败展期）→ `HIGH_WATCH_BUT_NOT_DEFAULT`。
  - 无反证 → `INDIVIDUAL_ECL`（个别评估）。
- 备注：真正的逾期起点是 DPD>0；档位只用于监测迁徙。

### C. 展期识别（4 类）
- **显性展期**：`current_due_date > original_due_date` 且存在有效展期记录。
- **无记录改期**：`current_due_date > original_due_date` 且无展期记录 → 内控红色异常。
- **疑似滚动展期**：老款 `original_dpd > 0` 且到期后仍有新赊销、最老超期未显著减少、回款偏向新发票。
  只标「疑似」，强制人工调查，**不定性舞弊**。
- **困难让渡**：展期原因含财务困难信号或人工标记。

### D. 授信调整触发
- 升额信号：高价值 + 授信长期充分使用 + 按期回款稳定 + 无未解决高风险展期 + 风险分可接受。
- 降额/缩账期信号：DPD 持续恶化 / 90+ 无反证 / 频繁或失败展期 / 授信使用率持续满额 / 实际毛利转负。
- 停供信号（只用硬事实）：未批准超限 / 明确减值证据 / 失败展期且无新还款增信方案。

### E. 四级动作体系
- 绿色：无硬异常 → 自动监测，保持额度/库存。
- 黄色：进入预警区（DPD 初期恶化；库龄>180 天但有销售）→ 责任人队列，密集监测。
- 橙色：多指标叠加 / 反复展期 / 毛利明显侵蚀 / 高库存+低毛利 → 风控/业务联合审批。
- 红色：未批准超限 / 减值证据 / 失败展期 / 项目预测亏损 → 即时升级。
- 每个客户（应收侧）与物料×组织（库存侧）各算一档。

### F. 人工 override 审计
- 扩展审核 POST（`/api/v1/cases/{id}/reviews`）：新增可选字段 `override_status`（APPROVED/REJECTED）、
  `override_reason`、`override_expiry_date`、`approver`。
- **保留原始规则命中**（不删除 rule_hit），新增审计记录字段：`rule_hit`、`override_status`、
  `override_reason`、`override_expiry_date`、`approver`、`next_review_date`、`input_timestamp`、
  `evidence_json`。
- 页面（案件工作台人工审核 Tab + 治理中心）展示 override 历史，防「反复覆盖形成永不逾期假象」。

## 范围外（YAGNI）
- 不做模型驱动的评分（评分全部确定性，权重/分位写入口径可校准）。
- 不做真实 ROC/PR（无结果标签）、项目 Gantt（无验收数据）。
- 不引入 Pinia / TypeScript / 暗色模式。
- 不改动已有案件调查、规则引擎与证据契约的现有行为。
